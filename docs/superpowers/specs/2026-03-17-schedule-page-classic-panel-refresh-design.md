# Schedule Page Classic Panel Refresh Design

**Date:** 2026-03-17

## Context

当前日历页主要问题集中在三个点。

第一，月历格子偏大，日期和事件摘要被挤压，月底日期在视觉上不完整，像 3 月 28、29、30 这类日期和下方摘要内容容易显示不全。

第二，右侧面板现在是“手动添加进程”优先，信息层级不对。用户真正高频查看的是“当天安排”和“今日待办”，而不是每次都先看到新增表单。

第三，OpenClaw 在聊天成功后目前只触发待办刷新，日历页本身不会同步更新日程数据，导致用户需要手动刷新页面才能看到刚刚被 AI 改动的内容。

## Goal

把日历页调整成一个更稳定、更经典的工作台布局：

1. 左侧月历更紧凑，日期和摘要可见性更好；
2. 右侧默认展示经典的“当天安排 + 今日待办”面板；
3. 手动添加进程改成可展开区域，默认收起；
4. OpenClaw 更新数据后，只刷新页面上正在显示的数据，不做整页刷新。

## Non-Goals

- 这一轮不改整个日历页的配色方向。
- 这一轮不重写日程数据模型。
- 这一轮不增加新的 OpenClaw API 接口。
- 这一轮不把所有页面都改成统一实时订阅。
- 这一轮不改动顶部导航、路由结构、现有 AI 聊天主流程。

## User-Approved Scope

用户确认采用方案 A：

- 左侧月历缩小并压紧；
- 右侧改成经典列表面板；
- 手动添加区域默认折叠；
- OpenClaw 成功后局部刷新显示数据；
- 其他行为和整体页面结构尽量保持不变。

## Approaches Considered

### Approach A: 保留单页结构，重排右侧信息层级并增加局部刷新事件

在现有 `SchedulePage.tsx` 基础上：

- 压缩月历格子尺寸和内部间距；
- 右侧改为“当天安排 + 今日待办 + 折叠表单”；
- 引入一个比 `workbench-todos-refresh` 更宽一点的数据刷新事件，让日历页只重拉自己需要的数据。

Pros:
- 改动集中；
- 不需要新增路由；
- 风险最低；
- 用户感知最直接。

Cons:
- `SchedulePage.tsx` 会继续承担较多视图拼装责任；
- 需要给现有待办组件补少量可复用能力。

### Approach B: 把日历页拆成多个新组件，并建立专门的页面级状态容器

把月历、右侧经典面板、折叠表单、刷新事件都拆成独立组件与 hook。

Pros:
- 架构更整洁；
- 后续扩展容易。

Cons:
- 对这轮需求来说偏重；
- 会引入额外文件移动和样式迁移；
- 超出“其他都不变”的范围。

### Approach C: 保持 UI 不动，只修 CSS 和轮询刷新

只缩小月历尺寸，右侧原样保留，再让日历页定时轮询最新数据。

Pros:
- 改动最少；
- 很快可交付。

Cons:
- 右侧信息层级问题没有真正解决；
- 轮询会带来无意义请求；
- 不符合“懒加载、只变数据”的方向。

## Decision

选择 **Approach A**。

这轮目标不是重构整套日历系统，而是在不破坏现有页面习惯的前提下，把信息优先级和刷新体验拉到可用状态。Approach A 能以最小风险完成这件事。

## Design

### 1. 左侧月历改成紧凑版

月历区仍保留左大右小的总体布局，但要缩小单元格占用。

具体方向：

- 减少月历单元格的内边距；
- 减少日期字号和事件摘要的垂直间距；
- 允许单元格内最多显示两条极短摘要；
- 把顶部周标题和月份标题的间距再压紧一点；
- 保证月底日期和摘要在常见桌面宽度下完整可见。

实现重点不是硬塞更多内容，而是让“日期数字 + 1 到 2 条摘要”稳定显示，不再因为格子太松导致信息浪费。

### 2. 右侧改成经典工作台面板

右侧面板的信息顺序调整为：

1. 选中日期标题；
2. 当天安排列表；
3. 今日待办列表；
4. 折叠的“手动添加进程”区域；
5. 辅助性的事件类型说明。

这里的“经典”不是重新设计一套复杂视觉，而是回到更清楚的信息分层：

- 先看内容；
- 再看待办；
- 最后才是录入。

右侧面板仍保持单列滚动，但默认视觉重心不再被表单抢走。

### 3. 手动添加进程改为默认折叠

“手动添加进程”改成可展开卡片，默认关闭。

折叠态只显示：

- 区块标题；
- 一个展开按钮；
- 轻量说明文案。

展开后才展示现有输入项：

- 标题；
- 时间；
- 说明；
- 类型；
- 添加按钮。

收起时不清空用户已输入内容，避免误操作丢失。

### 4. 今日待办复用现有工作台数据源

右侧的“今日待办”不单独造新接口，直接复用现有工作台待办 API 和当前的待办刷新机制。

但为了适应日历页，需要补一个“面板版”展示方式：

- 维持经典列表式排版；
- 默认展示数量比 Dashboard 的 5 条略宽松；
- 样式上更贴近右侧信息栏，而不是卡片型摘要。

如果现有 `TodayTodos` 组件经过少量参数化即可满足，就优先参数化复用；如果参数化会让它过度复杂，就在日历页附近加一个轻量的日历专用待办面板组件。

这一轮把右侧待办面板明确为 **可交互面板**，不是只读列表：

- 保留现有待办组件已经具备的新增、勾选完成、删除能力；
- 不额外新增新的待办能力；
- 只调整展示位置、展示样式和可见条数。

这样可以保持“经典 to-do list”的使用感，同时不扩展功能范围。

### 5. OpenClaw 成功后改成“局部懒刷新”

当前 AI 聊天成功后只派发 `workbench-todos-refresh`，这会让待办变，但不会让日历事件列表变。

这一轮新增一个更通用的页面数据刷新事件，例如：

- `workbench-data-refresh`

事件语义：

- 只表示“某些工作台数据可能已被 OpenClaw 更新”；
- 页面自己决定要不要刷新、刷新哪些数据；
- 不要求整页 reload。

日历页收到事件后：

- 只重拉当前月份的日程事件；
- 右侧“当天安排”不做单独请求，而是始终从这份当前月份事件数据派生；
- 保持当前选中日期、滚动位置和打开/收起状态不变。

AI 聊天成功后：

- 继续派发现有待办刷新事件；
- 同时派发新的通用数据刷新事件。

这样能满足“数据更新，但界面壳子不重置”的要求。

### 6. 刷新策略保持懒触发而不是轮询

这轮不引入定时轮询。

新事件 `workbench-data-refresh` 只用于 OpenClaw 成功后的局部刷新。

触发条件只在下面这一类成功动作后发生：

- OpenClaw 聊天成功返回；

日历页内部已有的本地动作，例如手动新增日程成功，继续直接调用自己的 `loadEvents()` 即可，不复用新的全局事件。

这样既能保证数据同步，又不会因为无意义轮询让页面感觉更重，也不会把事件边界扩得太散。

## Data Flow

### 日历页首次进入

1. `SchedulePage` 拉取当前月份日程；
2. 右侧“当天安排”从当前月份事件中过滤出选中日期的数据；
3. 今日待办面板按自己的既有机制拉取待办数据。

### 用户在右侧展开并新增日程

1. 提交新增请求；
2. 成功后刷新当前月份事件；
3. 保持选中日期和面板状态；
4. 如有详情浮层，同步显示新增结果。

### OpenClaw 成功修改数据

1. `AIChatWidget` 请求成功；
2. 派发 `workbench-todos-refresh`；
3. 派发 `workbench-data-refresh`；
4. `SchedulePage` 监听后仅刷新当前月份事件；
5. 右侧“当天安排”从更新后的月份事件重新派生；
6. 今日待办面板继续由现有 `workbench-todos-refresh` 机制负责刷新；
7. 页面壳子、滚动位置、路由不变。

## Error Handling

- 日历事件刷新失败时，只显示日程区错误提示，不清空整页其他内容。
- 今日待办刷新失败时，只影响待办区，不影响月历与日程区。
- 折叠表单提交失败时，保留输入内容，允许用户继续修改后重试。
- OpenClaw 成功事件触发刷新时，如果某一块刷新失败，只对该块 toast，不整页打断。

## Testing

这一轮至少覆盖下面几类验证：

1. 日历页右侧折叠面板默认关闭，点击后可展开，再次点击可收起；
2. 月历压缩后月底日期仍能显示；
3. `workbench-data-refresh` 派发后，日历页会重新拉取当前月份事件；
4. OpenClaw 聊天成功后，会同时触发待办刷新和通用数据刷新；
5. `workbench-data-refresh` 触发后，当前选中日期、右侧滚动位置、折叠状态保持不变；
6. 折叠“手动添加进程”后，草稿输入内容不会被清空；
7. 手动新增日程成功后，右侧当天安排立即出现新增内容，且不刷新整页；
8. OpenClaw 成功修改数据后，右侧“当天安排”和“今日待办”都会在当前页原地更新，不触发整页 reload。
