# Schedule Page Tabbed Sidebar Design

**Date:** 2026-03-17

## Context

上一轮日历页已经把右侧栏从“先录入再看内容”改成了“先看内容再录入”，但现在还有一个明显问题没有收住。

右侧栏虽然已经变成单列滚动，但在常见笔记本高度下，`当天安排 + 今日待办 + 折叠表单 + 图例` 仍然容易把可视区挤满。结果是：

- 页面视觉上显得太高，像是被拖出屏幕外；
- 用户想看右侧底部信息时，需要先滚过中段内容；
- 图例的存在感偏强，却不是高频主任务；
- 当天安排和今日待办这两个核心区块都想保留，但同时完全展开会继续吃掉高度。

用户已经明确希望右侧更紧，并且接受把右侧主内容改成标签页切换的形式。

## Goal

把日历页右侧栏收成一个更稳定的“标签页主内容区”：

1. 右侧不再因为内容堆叠而把页面主体挤出屏幕；
2. `当天安排` 和 `今日待办` 共享同一块主内容区，通过标签切换；
3. 主内容区自身可上下滚动，不影响整个页面壳；
4. `手动添加进程` 继续默认折叠；
5. 图例缩小、弱化，避免继续占据主要高度。

## Non-Goals

- 这一轮不改左侧月历的整体视觉方向。
- 这一轮不新增新的日程接口或待办接口。
- 这一轮不重写 `TodayTodos` 的交互能力。
- 这一轮不引入复杂动画标签页或新的状态管理库。
- 这一轮不改 OpenClaw 的刷新语义，只沿用现有局部刷新。

## User-Approved Scope

用户已确认采用标签页方案：

- 右侧主内容改成 `当天安排 / 今日待办` 两个标签；
- 标签下面只保留一个主内容区；
- 主内容区自己滚动；
- `手动添加进程` 保持折叠；
- 图例缩小，不再把底部继续顶出去。

## Approaches Considered

### Approach A: 继续单列，但整体压得更紧

只继续缩小 padding、字号和卡片间距，让右栏单列继续往下叠。

Pros:
- 改动最小；
- 结构最接近当前实现。

Cons:
- 高度压力只是被延后，不是被解决；
- 当天安排和今日待办一旦都比较长，还是会继续挤占可视区；
- 用户已经明确偏向更强的结构收口。

### Approach B: 标签页切换单主内容区

右栏保留日期标题，下面放 `当天安排 / 今日待办` 标签，当前标签独占一块主内容区，主内容区内部滚动；折叠表单和小图例放在下面。

Pros:
- 最有效节省垂直空间；
- 结构清楚，用户容易理解；
- 不需要引入复杂的新组件体系；
- 能保住当天安排和今日待办的可交互性。

Cons:
- 在两个核心区之间切换会多一步；
- 需要给页面本地状态增加“当前标签”。

### Approach C: 当天安排与今日待办做成上下双区独立滚动

右栏中部保留两个同时可见的滚动区，各自显示当天安排和今日待办。

Pros:
- 两个核心区都一直可见；
- 不需要切换标签。

Cons:
- 视觉更碎；
- 小屏高度下两个滚动区都会偏矮；
- 交互复杂度和样式约束都更高。

## Decision

选择 **Approach B**。

这一轮的核心不是继续“挤一挤”，而是把右栏的高度结构真正收住。标签页方案最直接，也最符合用户已经给出的偏好。它能在保留现有功能的前提下，把右栏收成稳定的上中下三段：日期标题、标签主内容区、折叠辅助区。

## Design

### 1. 右栏改成固定头部 + 标签主内容区 + 辅助底部

右栏从当前的单纯纵向堆叠，改成更明确的三段结构：

1. 顶部：日期标题与简短说明；
2. 中部：标签按钮 + 当前标签的主内容区；
3. 底部：折叠的手动添加进程、小型图例。

其中真正占高度的只剩“主内容区”，而它自己负责滚动。这样整张页不会因为中部内容变多就被继续拉高。

### 2. 两个标签：当天安排 / 今日待办

主内容区只保留两个标签：

- `当天安排`
- `今日待办`

默认进入 `当天安排`，因为在日历页里，用户首先关注的是“选中的这一天有什么安排”。

切到 `今日待办` 时，仍然复用现有 `TodayTodos` 的交互能力，包括新增、勾选和删除；只是把它放在标签页内容区中显示。

刷新或本地交互之后，当前激活标签不应被重置，避免用户刚切到 `今日待办` 又被刷新打回去。

当用户在左侧月历重新选择日期时：

- `selectedDate` 立即更新；
- 顶部日期标题也立即切到新日期；
- 如果当前激活的是 `今日待办`，则保持留在 `今日待办` 标签，不强行跳回 `当天安排`；
- 用户下一次切回 `当天安排` 时，看到的是新日期对应的日程。

这样既保留标签上下文，也避免“点了日期但界面像没反应”。

### 3. 主内容区内部滚动，而不是整页继续向下堆

主内容区要明确拥有可用高度，并使用内部 `overflow-y-auto`。

这意味着：

- 右栏自身仍在页面高度内；
- 标签内容区拿到剩余空间；
- 当天安排很多时，只滚安排列表；
- 今日待办很多时，只滚待办列表；
- 页面外壳和顶部日期标题保持稳定。

实现边界也需要写清：

- 右栏根容器负责 `flex-col` 和整体高度约束；
- `ScheduleSidebarPanel` 负责标签状态、标签 chrome、主内容高度分配，以及“唯一主内容滚动边界”；
- 标签行下方有一个唯一的“主内容壳”，它负责拿走剩余高度；
- 真正的纵向滚动只属于这个主内容壳内部当前激活的标签内容；
- `TodayTodos` 作为被嵌入内容，必须放进这个父级高度壳里，保留自己的内容头部和列表交互，但不能再把右栏外层继续撑高。

响应式规则也要固定：

- 在 `xl` 及以上双栏布局里，右栏必须维持固定高度壳 + 内部滚动；
- 在低于 `xl`、右栏堆叠到月历下方时，不再强求同样的固定高度壳，可以回退到自然页面流；
- 也就是说，严格的“不要把外层栏位继续撑爆”目标主要约束双栏桌面布局。

### 4. 折叠表单继续保留，但弱化为辅助区

`手动添加进程` 继续默认折叠，并留在主内容区下方。

它不参与标签切换，因为它是辅助录入区，不是用户日常阅读主视图。标签切换应该只服务于两个高频主内容。

折叠/展开时仍需保留草稿；提交成功后再清空草稿，提交失败不丢内容。

### 5. 图例缩成轻量块

图例从当前相对完整的块状区域，缩成更小的轻量说明区。

原则：

- 只保留颜色点和文字；
- 缩小 padding、字号和上下间距；
- 放在折叠表单之后；
- 不再占据明显视觉焦点。

它的存在是辅助识别，不应该继续把关键内容往下推。

## Data Flow

### 首次进入

1. 日历页拉取当前月份事件；
2. 右栏默认激活 `当天安排` 标签；
3. 当天安排从当前月份事件中过滤出选中日期的数据；
4. 若切到 `今日待办`，则由 `TodayTodos` 自己拉取待办数据。

### 用户切换标签

1. 更新页面本地 `activeSidebarTab`；
2. 只切换主内容区，不重新请求日历事件；
3. 当前选中日期、草稿折叠状态、详情弹层状态保持不变。

### AI 局部刷新

1. 继续接收 `workbench-data-refresh`；
2. 页面只刷新当前月份事件；
3. 当前激活标签不变；
4. 若当前在 `当天安排`，刷新后直接反映新数据；
5. 若当前在 `今日待办`，待办仍由现有待办刷新事件处理。

## Error Handling

- 日程刷新失败时，不清空当前已显示的旧事件数据。
- 待办刷新失败时，不清空当前已显示的旧待办列表。
- 标签切换本身不应引入新的错误路径。
- 手动添加失败时，折叠状态和输入草稿保持原样。

## Testing Strategy

这一轮优先补页面本地状态测试，而不是新增浏览器测试框架。

重点验证：

1. 默认标签是 `当天安排`；
2. 切换标签后，本地状态正确更新；
3. 页面刷新时，当前激活标签保持不变；
4. 手动添加折叠/草稿行为仍不回退；
5. 前端类型检查与构建继续通过。

同时补充页面级验收标准：

6. 在桌面双栏布局下，右栏外层高度不再继续把页面主体往下顶；
7. 当前激活标签的内容区是唯一的纵向主滚动区，不出现“右栏外层和标签内容同时滚”的明显双滚动；
8. 切到 `今日待办` 后再点击左侧日期，顶部日期标题仍立即更新，但标签保持在 `今日待办`。

## Risks

- `SchedulePage.tsx` 继续增长，如果把 tab 状态和布局细节都堆进去，文件会更重。
- 如果主内容区高度约束写得不严，可能出现“标签页也能切，但仍然把外层撑爆”的假修复。
- `TodayTodos` 需要被放进更严格的高度容器里，否则它内部滚动可能和右栏滚动打架。

## Open Questions

这一轮没有新的产品性开放问题。

用户已经明确选定标签页方向，后续直接进入实现即可。
