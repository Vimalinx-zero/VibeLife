# 本地音乐库导入设计

## 目标

给 VibeLife 增加一套用户级全局音乐库。用户可以从本地一次导入多个音频文件，或者直接导入一个音乐文件夹。后端会把音频复制到 VibeLife 自己的目录里持久化保存，Workbench 的专注播放器优先使用这套用户音乐库。

## 范围

本轮只做最小可用版本：

- 支持 `选择文件夹`
- 支持 `选择多个文件`
- 后端复制保存音频文件
- 数据库保存音乐条目元数据
- Workbench 播放器可以读取并播放导入的音乐
- 如果用户音乐库为空，回退到现有默认远程曲库

本轮不做：

- 音乐封面抓取
- 歌词
- 智能标签推荐
- 复杂音乐管理页
- 拖拽排序
- 批量删除/重命名

## 用户体验

Workbench 音乐播放器增加一个轻入口，用户可以看到：

- `导入音乐`
- `选择文件夹`
- `选择文件`

导入完成后：

- 新音乐直接出现在播放列表
- 当前会话无需刷新页面即可播放
- 后续再次打开 VibeLife 时仍然存在

如果导入失败，要给出明确提示，例如：

- 文件格式不支持
- 文件过大
- 上传失败
- 后端保存失败

## 数据模型

新增用户音乐表，按 `user_id` 隔离。

建议字段：

- `id`
- `user_id`
- `title`
- `artist`
- `album`
- `duration_seconds`
- `mime_type`
- `file_size`
- `stored_filename`
- `stored_path`
- `original_filename`
- `source_kind`，固定先用 `imported`
- `created_at`
- `updated_at`

第一版允许 `artist`、`album`、`duration_seconds` 为空或默认值。不要把元数据解析做成阻塞前提。

## 文件存储

后端为每个用户维护独立音乐目录，例如：

- `backend/uploads/music/<user_id>/`

导入时将文件复制进去，并生成唯一存储名，避免重名覆盖。

规则：

- 原文件名保留在数据库字段中
- 实际落盘文件名使用唯一 ID 或 UUID 前缀
- 只允许音频扩展名：`mp3`、`m4a`、`wav`、`ogg`、`flac`

## 后端接口

新增最小接口集：

- `GET /api/music/library`
  - 返回当前用户的音乐列表
- `POST /api/music/import`
  - 接收多文件上传
  - 保存文件到用户音乐目录
  - 创建数据库记录
- `GET /api/music/files/{music_id}`
  - 返回音频文件流或静态文件响应

接口要求：

- 所有查询必须按 `user_id` 过滤
- 上传接口必须校验 MIME 和扩展名
- 不信任前端传入文件名

## 前端架构

前端新增一层用户音乐库状态，不把导入逻辑硬塞进 UI 组件。

建议分层：

- `frontend/src/utils/api.ts`
  - 增加音乐库 API
- `frontend/src/context/MediaContext.tsx`
  - 加载用户音乐库
  - 优先使用用户音乐
  - 保留现有播放、切歌、进度逻辑
- `frontend/src/components/MusicPlayer.tsx`
  - 增加导入入口
  - 保持现有播放器视觉结构

导入流程：

1. 用户在 Workbench 点 `导入音乐`
2. 选择文件夹或文件
3. 前端把文件批量发给后端
4. 后端返回创建成功的音乐记录
5. 前端刷新音乐库并更新播放列表

## 兼容策略

`MediaContext` 的曲目来源改成：

1. 先读用户音乐库
2. 如果用户音乐库非空，就用用户音乐库
3. 如果为空，再退回 `FOCUS_COMPANION_TRACKS`

这样现有 Workbench 不会因为用户还没导入音乐而无歌可播。

## 验证

至少验证这些场景：

- 多选导入 2 到 3 首音乐成功
- 文件夹导入成功
- 导入后刷新页面仍可看到歌曲
- 播放器能播放导入歌曲
- 用户 A 的音乐不会出现在用户 B 下
- 非法扩展名被拒绝
- 空音乐库时仍能回退到默认曲库

## 风险与控制

风险：文件越来越多导致磁盘占用增长。

控制：

- 第一版先限制单文件大小
- 先不做自动去重，避免把逻辑做复杂
- 后续如有需要，再补删除和库管理

## 推荐实现策略

按下面顺序推进：

1. 后端模型与存储目录
2. 后端导入与列表 API
3. 前端 API 封装
4. `MediaContext` 接入用户音乐库
5. `MusicPlayer` 增加导入入口
6. 真实导入与播放验证
