## 🎯 优先级说明

| 级别 | 说明 | 响应时间 |
|------|------|----------|
| **P0 紧急** | 阻塞使用的 bug、安全漏洞、数据丢失 | 立即处理 |
| **P1 高** | 核心功能、用户强烈需求 | 24 小时内 |
| **P2 中** | 性能优化、文档完善、小功能 | 3 天内 |
| **P3 低** | 长期目标、探索性想法 | 1 周内 |

## 🔍 关键词识别

我能够识别以下类型的关键词，自动设置正确的分类和优先级：

### 功能类关键词
- **主要**: 功能、新增、添加、实现、feature
- **次要**: 模块、组件、接口
- **示例**: "我想添加..."、"需要实现..."、"新增..."、"支持...功能"

### Bug 类关键词
- **主要**: bug、错误、问题、异常、不工作、失败
- **次要**: 报错、卡住、崩溃、异常
- **示例**: "有个bug..."、"不工作了..."、"报错了..."、"卡住了"

### 优化类关键词
- **主要**: 优化、性能、慢、加速、提升、reduce
- **次要**: 延迟、卡顿、超时
- **示例**: "太慢了..."、"加载很慢..."、"可以优化..."

### 需求类关键词
- **主要**: 需要、希望、想要、应该、wish、should
- **次要**: 要是、要有
- **示例**: "我希望..."、"应该有个..."、"我想要..."

### 文档类关键词
- **主要**: 文档、说明、指南、example、readme
- **次要**: 注释、帮助、教程
- **示例**: "文档应该..."、"需要加个说明..."、"添加个指南"

## 📝 日常使用建议

### 1. 随时记录

- 工作中或学习时有想法立即告诉我
- 不用等到想不起来再记录
- 我会自动格式化和分类

### 2. 定期回顾

- 建议每周回顾一次想法列表
- 删除过期或已完成的想法
- 评估优先级是否需要调整

### 3. 充分讨论

- 重要想法可以创建 GitHub Issue 讨论
- 多人协作建议使用 Issue 而非简单的对话
- 讨论记录会自动添加到 IDEAS.md

### 4. 追踪进度

- 定期更新想法状态
- 记录重要的讨论和决策
- 实施完成后及时归档
